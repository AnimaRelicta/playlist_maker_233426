# Спринт 5 — архитектура и фича поиска

Предыдущий этап: [спринт 4](sprint4.md). Ветка — от завершённой `feature/sprint-04`.

## 1. Данные и Domain

- Разделить Data / Domain / UI; UI не обращается к Data напрямую.
- Track: id, название, исполнитель, длительность. TrackDto — модель Data при маппинге.
- Источник — локальный эмулятор Storage / NetworkClient, настоящий API пока не нужен.
- Интерфейс TracksRepository в Domain, реализация в Data.
- Suspend-поиск по части названия и исполнителя без учёта регистра.
- Фильтрация в Data; преобразование миллисекунд в `mm:ss` вне UI.
- Сымитировать асинхронный запрос задержкой (в примере — 3 секунды).
- В примере восемь композиций The Beatles; исходные названия и времена указаны в материалах курса.

## 2. MVVM и UI

Этот блок уже присутствует в предоставленном файле спринта 5.

- SearchViewModel: закрытый MutableStateFlow и публичный StateFlow.
- Состояния Initial, Searching, Success со списком, Fail с ошибкой.
- SearchScreen подписан на ViewModel, лупа запускает поиск.
- Показывать загрузку, результаты, пустую выдачу, ошибку.
- LazyColumn с кликабельными строками: обложка-заглушка, название, исполнитель,
  разделитель, длительность, стрелка.
- Очистка поля скрывает результаты и отменяет устаревший запрос.
- Нажатие на трек открывает детали с данными выбранной композиции.
- MainActivity остаётся launcher; маршруты и зависимости подключаются в PlaylistHost.

Пустая успешная выдача и ошибка источника — разные ситуации. В примерах есть разные
варианты их моделирования; итоговый UI должен различать их.

## 3. Koin

- Подключить Koin; создать модуль репозитория/клиента в Data и модуль ViewModel.
- Запускать Koin из Application, указать Application в манифесте.
- Получать зависимости через Koin, убрать прежнюю ручную фабрику после миграции.

## Приёмка и тесты

- Подстрока, регистр, исполнитель, пустой запрос, отсутствующая композиция.
- Время: ноль, секунды, минуты, длинный трек.
- Состояния, очистка во время запроса, последний запрос, ошибка и повтор.
- Проверка DI-графа, архитектурных зависимостей, клика по строке и данных деталей.
- Сборка, lint, UI-сравнение с Figma.

## Пересечение со спринтом 6

В исходнике 5 уже есть MVVM, а исходник 6 вводит его повторно. Это сохранено явно:
спринт 5 создаёт связку по своим материалам, спринт 6 проверяет потоки и состояния,
доводит приложение до готовности к ревью.
